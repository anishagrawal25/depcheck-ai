# depcheck-ai 🛡️

**AI-Assisted Dependency Security & Hallucination Scanner**

`depcheck-ai` protects modern software supply chains by detecting **hallucinated**, **typosquatted**, **unmaintained**, or **vulnerable** package dependencies in code generated by Large Language Models (LLMs) and developers alike.

---

## 🎯 The Problem

AI coding assistants (such as Copilot, ChatGPT, Claude, and Gemini) frequently generate functional code that imports dependencies that either:
1. **Do not exist on PyPI (Package Hallucination)**: Attackers register these hallucinated names on PyPI with malicious payloads (a documented vector known as *slopsquatting* or *AI package hallucination attack*).
2. **Are typosquats of popular libraries**: Malicious packages designed to mimic established libraries (e.g., `reqeusts`, `numpyy`, `flaks`).
3. **Have known critical vulnerabilities**: Outdated or vulnerable versions indexed in the Open Source Vulnerabilities (OSV) database.
4. **Invoke hallucinated API calls**: The library exists, but the referenced method or class does not exist in the public API (e.g., calling `requests.gett(...)` instead of `requests.get(...)`).

`depcheck-ai` provides proactive detection before malicious or broken code enters production environments.

---

## 🏗️ Architecture & Pipeline

`depcheck-ai` employs a multi-tiered inspection pipeline combining deterministic static analysis, live registry lookups, vector documentation retrieval (RAG), and agentic reasoning:

```
[ Input Code / Requirements ]
              │
              ▼
    [ AST Dependency Parser ]
     - Extracts imports & aliases
     - Filters Python stdlib modules
     - Maps import names to PyPI distributions
     - Extracts API symbol call patterns
              │
              ├──────────────────────────────────┐
              ▼                                  ▼
[ PyPI Registry & Metadata ]           [ Typosquatting Engine ]
 - Existence check                      - Levenshtein distance against
 - Age, release count, repo URLs          top popular PyPI packages
              │                                  │
              ├──────────────────────────────────┘
              ▼
[ OSV Vulnerability Check ]
 - Queries api.osv.dev for CVEs
              │
              ▼
[ Weighted Risk Scoring Engine ]
 - Computes risk score (0.0 - 1.0)
 - Assigns verdict: `ok` | `suspicious` | `hallucinated`
 - Produces structured human-readable reasons
              │
              ├──────────────────────────────────┐
              ▼ (Fast Rule Mode)                 ▼ (Autonomous Agent Mode)
    [ Scan Report Output ]              [ LangGraph Agent ]
                                         - Chroma RAG documentation search
                                         - Public API symbol verification
                                         - Recursive tool use (max 6 steps)
                                         - Step-level JSON tracing & Langfuse
                                         - Refined verdict & suggested fixes
```

### Key Components

1. **AST Parser (`app/parser.py`)**: Parses Python AST to extract all top-level and inner dependencies, resolves aliases, maps common imports (e.g., `PIL` -> `Pillow`, `yaml` -> `PyYAML`, `sklearn` -> `scikit-learn`), and extracts function/attribute calls.
2. **Registry & Typosquat Checker (`app/pypi.py`, `app/checks/typosquat.py`)**: Verifies existence on PyPI, retrieves package age, release count, repository URLs, and identifies potential typosquats within edit distance thresholds.
3. **Vulnerability Lookup (`app/checks/osv.py`)**: Queries the OSV API for known security advisories affecting the package.
4. **Scoring Model (`app/scoring.py`)**: Weighted risk assessment incorporating nonexistence (0.50), typosquatting (0.25), zero repository presence (0.10), recent release age (0.10), and vulnerability counts (0.05).
5. **RAG Public API Verification (`app/rag/`, `app/checks/api_verify.py`)**: Uses a Chroma vector database indexed with top package public API symbols and documentation to verify whether invoked methods actually exist in the package API.
6. **Investigation Agent (`app/agent/graph.py`, `app/agent/tools.py`)**: LangGraph state graph equipped with 5 specialized inspection tools (`check_registry`, `search_docs`, `check_osv`, `find_similar_package`, `verify_api_call`), with a 6-call budget cap and automated step tracing.

## 🚀 Quick Start

### 1. Installation

Clone the repository and set up a Python virtual environment:

```bash
git clone https://github.com/anishagrawal25/depcheck-ai.git
cd depcheck-ai
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Run the FastAPI Backend

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Endpoints:
- `GET /health`: Health and readiness probe.
- `POST /scan`: Scans Python code or `requirements.txt`.
  - Query parameters:
    - `mode`: `"rule"` (default) or `"agent"`.
    - `use_llm`: `false` (default) or `true` (enables LLM explanations for non-ok findings).

Example request:
```bash
curl -X POST "http://localhost:8000/scan?mode=rule" \
  -H "Content-Type: application/json" \
  -d '{"code": "import requests\nimport fastjsonparserx"}'
```

### 3. Run the Streamlit Interactive UI

```bash
streamlit run ui.py
```

Open `http://localhost:8501` to use the interactive dashboard with:
- Code editor & example snippets (*Clean*, *Fake Package*, *Typosquat*).
- Inspection mode toggle (**Rule-based** vs **Agent-based**).
- Color-coded security verdicts (`ok`, `suspicious`, `hallucinated`).
- Detailed risk explanations and suggested fixes.

### 4. Run with Docker Compose

Run the entire stack (FastAPI backend + Streamlit UI) in Docker:

```bash
docker compose up --build
```
- API accessible at `http://localhost:8000`
- Web UI accessible at `http://localhost:8501`

## 🔍 RAG Ingestion & API Verification

`depcheck-ai` can index public API symbols for popular libraries:

```bash
python scripts/ingest.py
```

This reads packages from `data/rag_packages.txt`, inspects public symbols and documentation, and populates the local Chroma vector store (`data/chroma`).

## 📈 Tracing & Observability

`depcheck-ai` includes built-in step-level tracing for autonomous agent investigations:
- **Local JSONL Traces**: Every tool invocation records its latency, status, arguments, and output in `logs/traces.jsonl`.
- **Langfuse Integration**: Optional production tracing with [Langfuse](https://langfuse.com). Simply configure:
  ```bash
  export LANGFUSE_PUBLIC_KEY="pk-..."
  export LANGFUSE_SECRET_KEY="sk-..."
  export LANGFUSE_HOST="https://cloud.langfuse.com"
  ```

## ⚠️ Limitations & Future Work

- **Dynamic Imports**: Imports evaluated at runtime via `__import__()` or `importlib.import_module()` with computed string expressions are not captured by AST parsing.
- **Transitive Dependencies**: The scanner currently inspects first-order dependencies declared in the snippet; transitive dependency tree resolution is planned for v0.2.
- **Multi-Ecosystem Support**: Currently focused on Python / PyPI; future releases will expand support to npm, Maven, and Crates.io.
